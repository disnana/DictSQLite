## 3. 同期版 vs 非同期版 比較

### パフォーマンス特性

| 項目 | 同期版 | 非同期版（並行実行） | 備考 |
|------|--------|---------------------|------|
| **個別書き込み** | 567.29K ops/s | 19.76K ops/s | 同期版が高速 |
| **個別読み込み** | - | 144.91K ops/s | 並行実行で高速 |
| **バルク書き込み** | 340.94K ops/s | - | 同期版が高速 |
| **バルク読み込み** | 283.77K ops/s | - | 同期版が高速 |
| **並行度の影響** | なし | 2.6倍向上（並行度100） | 非同期版の強み |

### 重要な考察

#### 1. なぜ同期版のOPSが高いのか？

- **同期版**: ディスク I/O、メモリアクセスを最適化した純粋なスループット
- **非同期版**: asyncioのオーバーヘッド、タスク切り替えのコスト
- **順次処理の場合**: 同期版が圧倒的に有利

#### 2. 非同期版の真の価値

- **並行実行時の効率**: 並行度を上げることで2.6倍の性能向上
- **I/O待機時間の活用**: 他の処理を同時実行可能
- **レスポンシブネス**: Webアプリケーションでブロッキングなし

#### 3. 並行度とパフォーマンスの関係

非同期版では並行度を上げることで性能が向上：
- 並行度 1 → 10: **1.9倍向上**
- 並行度 1 → 50: **2.6倍向上**
- 並行度 1 → 100: **2.6倍向上**（50以降は横ばい）

最適な並行度は **50-100程度**

## 4. 使い分けの指針

### 同期版（DictSQLiteFastestBeta）を選ぶべきケース

✅ **バッチ処理やデータ移行**
- 最大スループット: 567K ops/s（個別）、341K ops/s（バルク）
- メモリ予算による自動最適化で設定が簡単

✅ **単一プロセスでの高速処理**
- データベース全体のエクスポート/インポート
- 大量データの一括変換

✅ **シンプルな実装**
- 非同期処理の複雑さが不要な場合

### 非同期版（AsyncDictSQLiteFastestBeta）を選ぶべきケース

✅ **Webアプリケーション**
- FastAPI、aiohttp等での使用
- 複数のクライアントからの同時アクセス
- レスポンシブネスが重要

✅ **並行処理が必要な場合**
- 複数のデータソースからの並行読み込み
- I/O待機時間を有効活用

✅ **リアルタイム性が重要**
- 一つの処理で他の処理をブロックしない

## 6. 測定方法の詳細

### 同期版

```python
# 個別書き込みテスト
for i in range(10000):
    db[f'key_{i}'] = f'value_{i}_' + 'x' * 50
```

### 非同期版（最適化）

```python
# 並行書き込みテスト（並行度100）
async def write_batch(start_idx, batch_size):
    tasks = [db.aset(f'key_{i}', f'value_{i}_' + 'x' * 50) 
             for i in range(start_idx, start_idx + batch_size)]
    await asyncio.gather(*tasks)

# 100件ずつ並行実行
for batch_idx in range(100):
    await write_batch(batch_idx * 100, 100)
```
