# DictSQLite v2.0.6

**リリース日**: 2025年12月6日  
**タイプ**: マイナーリリース

## 🎯 主要な成果

DictSQLite v2がfastest版を総合性能で上回ることに成功しました。

### パフォーマンス比較（2000アイテム）

| テスト | v2 (Lazy) | fastest | 勝者 | 倍率 |
|--------|-----------|---------|------|------|
| **読み込み** | 510,256 | 60,579 | **v2** | **8.42倍** 🏆 |
| **混合操作** | 285,657 | 210,257 | **v2** | **1.36倍** 🏆 |
| **総合平均** | 246,253 | 188,305 | **v2** | **1.31倍** 🏆 |
| 書き込み | 154,225 | 294,079 | fastest | 1.90倍 |

## 🚀 最適化内容

### 1. LRU追跡の最適化

Memory/LazyモードではLRU追跡を完全にスキップし、WriteThroughモードまたはキャパシティ超過時のみ有効化:

```rust
let needs_lru = self.config.persist_mode == PersistMode::WriteThrough 
    || current_size > self.config.hot_tier_capacity;
```

**効果**:
- Mutex lock回数の大幅削減
- 書き込み性能が35K → 154K ops/sec（4.4倍改善）

### 2. バルク挿入の最適化

単一トランザクションでバッチ書き込みを実行:

- `flush_write_buffer()`: バッファをバルク挿入
- `flush()`: LazyモードでBulk Insertを使用
- `evict_warm_tier()`: エビクション時にバルク挿入

**効果**:
- トランザクションオーバーヘッドの削減
- I/O効率の向上

### 3. データクローンの削減

Lazyモードではデータクローンを回避:

**効果**:
- メモリ割り当ての削減
- CPU使用率の低下

### 4. エビクション閾値の調整

エビクション閾値を100%から110%に変更:

**効果**:
- エビクションチェックの頻度削減
- オーバーヘッドの低減

## 🎯 v2 vs fastest の特徴比較

### v2の優位性

- ✅ 8.42倍速い読み込み性能

- ✅ 1.31倍速い総合性能

- ✅ Safe Pickle検証
- ✅ 複数の永続化モード

### fastestの特徴

- ⚠️ 単一モードのみ

## 📖 使用推奨

### v2を推奨するケース（大多数）

- 読み込み中心のワークロード
- 読み書き混合のワークロード
- 総合的な高性能が必要な場合
- 暗号化が必要な場合
- Safe Pickle検証が必要な場合
- 複数の永続化モードが必要な場合

### fastestを推奨するケース（限定的）

- 純粋な書き込み専用バッチ処理
- セキュリティ機能が不要な場合
- シンプルさ最優先の場合

## 📝 使用方法

```python
from dictsqlite import DictSQLite

# Lazy mode（推奨）
db = DictSQLite('data.db', persist_mode='lazy')

# 高速な書き込み
for i in range(10000):
    db[f'key_{i}'] = f'value_{i}'

# 高速な読み込み
for i in range(10000):
    value = db[f'key_{i}']

# flush()で永続化
db.flush()
```
