### なぜv2.0がこれほど速いのか

#### アーキテクチャの違い

```
┌─────────────┬──────────────────┬─────────────────┬──────────────────┐
│ 項目        │ v1               │ Fastest         │ v2.0             │
├─────────────┼──────────────────┼─────────────────┼──────────────────┤
│ データ保存  │ SQLite直接       │ APSWプール      │ メモリ+同期      │
│ 読み込み    │ 毎回ディスク     │ プール経由      │ 完全メモリ       │
│ 書き込み    │ 毎回ディスク     │ プール経由      │ メモリ+遅延同期  │
│ オーバーヘッド│ 高（ロック）    │ 中（プール管理）│ 低（メモリのみ） │
│ 同期        │ 同期的           │ 同期的          │ 非同期           │
└─────────────┴──────────────────┴─────────────────┴──────────────────┘
```

#### v2.0の成功要因

1. **完全メモリキャッシング**
   ```python
   self._cache: Dict[str, Any] = {}  # 全データをメモリに保持
   ```
   - 読み込み: O(1)、ディスクI/O不要
   - 書き込み: O(1)、メモリ更新のみ

2. **バックグラウンド同期**
   ```python
   def _sync_loop(self):
       while not self._stop_sync.is_set():
           time.sleep(self.sync_interval)
           self._sync_to_disk()
   ```
   - メイン処理をブロックしない
   - バッチ書き込みで効率化

3. **最適化されたSQLite設定**
   ```python
   cursor.execute('PRAGMA journal_mode=WAL')
   cursor.execute('PRAGMA synchronous=NORMAL')
   cursor.execute('PRAGMA cache_size=10000')
   ```

## 🔒 セキュリティ機能の実装

### 実装した機能

#### 1. AES-256暗号化

**特徴**:
- PBKDF2-HMAC-SHA256によるキー導出
- AES-256-CBC暗号化
- URLセーフBase64エンコーディング

**使用例**:
```python
from dictsqlite_v2 import DictSQLiteV2

db = DictSQLiteV2(
    "secure.db",
    encryption_password="YourSecurePassword"
)
db['secret'] = {'api_key': 'xyz123'}
```

**パフォーマンス**:
- 暗号化なし: 1.5M ops/sec
- 暗号化あり: 1.0M ops/sec（-30%だが依然として高速）

#### 2. Safe Pickle

**特徴**:
- ホワイトリストベースのポリシー
- 任意コード実行の防止
- カスタムポリシー対応

**使用例**:
```python
db = DictSQLiteV2(
    "safe.db",
    use_safe_pickle=True
)
# 基本型のみ許可
db['data'] = [1, 2, 3]
```

**パフォーマンス**:
- 影響: わずか1-2%（ほぼ無視できる）

#### 3. 組み合わせ使用

```python
# 最大限のセキュリティ
db = DictSQLiteV2(
    "ultra_secure.db",
    encryption_password="password",
    use_safe_pickle=True
)
```

2. **設定管理**
   - アプリケーション設定

   - 環境変数

   - 数千〜数万件のレコード
   - メモリに収まるサイズ

   - リアルタイムアプリケーション

### ❌ 向いていない

   - GB級のデータ

2. **複雑なクエリ**
   - JOIN操作
   - 複雑な検索条件
   - 集計処理

3. **厳密な即時同期**
   - トランザクションの即時永続化
   - 障害時の完全なデータ保証
